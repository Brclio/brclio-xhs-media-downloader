# 桌面版

## 安装与使用

从 [GitHub Releases](https://github.com/Brclio/brclio-xhs-media-downloader/releases) 下载对应系统安装包。Mac Apple 芯片选择 `mac-arm64.dmg`；Windows 选择 `windows-x64-setup.exe`（安装版）或 `windows-x64-portable.exe`（便携版）。

最终安装包自带运行环境，使用者不需要 Python、Node.js、Chrome 或 Vercel CLI。Mac 需要选择与芯片匹配的版本（Apple 芯片 arm64 / Intel x64），Windows 使用 x64 版本。

1. 安装并打开应用。原来的“单篇下载”保留网页版全部媒体功能和 Node.js / Python 引擎选择。
2. 切换“主页下载”，粘贴完整个人主页链接，例如 `https://www.xiaohongshu.com/user/profile/5e413a430000000001000f4c`。
3. 点击登录按钮，在应用的独立小红书窗口完成登录；成功后按钮显示“已登录 · 当前账号昵称”。如出现验证码，需要本人完成验证。
4. 选择保存文件夹，设置抓取间隔与额外随机等待，开始任务。Mac 首次访问“下载”或“文稿”文件夹时，请在系统提示中允许访问；从开发版切换为正式应用可能需要重新授权。
5. 等待列表收集和逐篇下载。可以暂停后继续；关闭应用后，下次打开需要手动继续任务。

主页列表通过小红书正常网页加载和滚动读取，详情通过同一登录会话打开。应用不使用猜测的 API 签名，不绕过验证码。只读取该作者发布的笔记，不收集点赞、收藏、关注者或相关推荐。

**Chrome、Codex 内置浏览器与下载器的登录状态互不共享。** 即使浏览器已经登录，下载器首次使用仍需在自己的窗口登录一次。之后账号会话仅保留在本机；退出登录、Cookie 过期或访问他人主页再次遇到登录检查时，任务会暂停，重新登录后可继续。

## “全部下载”的范围

“全部”指抓取期间该主页向当前登录账号公开展示、且可以打开详情的帖子。平台返回列表结束标记后才认定列表已完整；仅仅滚动没有新增内容不算结束。遇到登录、验证或列表停滞会保留进度并提示继续。

帖子可能在任务期间新增、删除或修改。已保存文件不会持续自动同步；要重新检查主页，请再次建立该主页任务。失败条目可重试。没有可下载媒体或不能确认完整详情的帖子会记为失败，不会只保存一张封面后当成成功。

默认请求间隔为 10 秒，加上最多 3 秒的随机等待。自定义间隔至少为 3 秒；每篇详情和每个媒体按队列顺序处理。正常网页本身仍会加载页面所需资源。间隔控制降低应用主动访问的频率，不能保证平台永不限流。

所选文件夹中，每篇帖子用笔记 ID 单独建目录，原图、实况 JPG + MP4、默认视频流、`笔记.txt` 和 `笔记.json` 一起保存。批量主页下载直接写入硬盘，不把整份主页媒体放进内存生成巨型 ZIP；单篇原有 ZIP 功能仍然可用。视频保存一个默认流，多清晰度可在单篇页选择下载。实况为配对素材，不会自动生成 Apple Photos 原生 Live Photo 元数据。

成功文件经过大小与 SHA-256 校验后才跳过；未完成媒体使用临时文件，完成后再改名。任务状态保存在应用用户数据目录，保留帖子链接、进度和目标路径；Cookie 由 Electron 的独立持久会话保存在本机，不写入任务清单。

## 开发与发布

开发机才需要 Node.js（22 或更新版）和 Python（用于构建内置独立引擎）。普通使用者无需这些工具。

```bash
npm ci
npm run desktop:dev
```

在 Mac 上构建当前芯片版本（采用固定版本、校验 SHA-256 的独立 Python，避免开发机的 Homebrew Python 抬高最低系统要求）：

```bash
npm run desktop:prepare:mac
npm run desktop:build:mac
```

在 Windows 上构建 x64 安装版与便携版：

```powershell
npm run desktop:prepare:windows
npm run desktop:build:win
```

输出在 `dist-desktop/`：Mac 为 `.dmg` / `.zip`，Windows 为 `-setup.exe` / `-portable.exe`。Mac arm64 面向 Apple 芯片，最低 macOS 13；Intel Mac x64 由同一流程在 Intel 构建机或 CI 构建。Windows 包面向 Windows 10/11 x64。便携版同样包含完整运行环境，但任务与登录数据仍保存在当前系统用户的应用数据目录。

开发者可在 GitHub Actions 中手动运行 `Desktop installers`，或推送 `v*` / `desktop-v*` 标签。矩阵分别构建 Mac arm64、Mac x64、Windows x64，并上传可下载的安装包附件。构建输出不会自动公开发布。发布包必须包含对应操作系统、CPU 架构的 Python 引擎；缺少引擎时构建失败，本机原生构建还会实际启动引擎验证，不能产出要求用户自行安装 Python 的“完整安装包”。

Mac 的 Apple 签名 / 公证和 Windows 的代码签名需要发布者配置自己的证书。未配置证书的构建是未签名测试包，分发时系统可能提示无法验证开发者。正式发布前应在目标系统上执行安装、启动、登录、下载和卸载验收。

## 验证与限制

```bash
npm test
```

另外可运行真实 Electron 验证（创建独立临时会话，不读取日常登录信息）：

```bash
node_modules/.bin/electron scripts/verify-desktop.mjs
node_modules/.bin/electron scripts/verify-profile.mjs
```

测试覆盖原有 Node.js / Python 解析器、主页 URL 与列表完成判断、队列恢复、间隔等待、媒体下载边界、登录昵称和桌面协议。详情测试包含 Vue 循环引用、实况视频晚于图片加载、视频封面先于视频流加载的情况。桌面启动验证检查真实主进程、预加载桥接、两套引擎调用，并保存窗口截图。

2026-09-20 在 Mac 上使用实际登录会话验收：示例主页读到明确结束标记，共发现 240 篇；多图帖子、文案及 JSON 已实际落盘，实况 MP4 与普通视频样本也已下载并通过大小与 SHA-256 校验。登录按钮显示当前账号昵称，重启后恢复登录和任务。此验收不代表 240 篇均已下载完成。Windows 安装包已生成并检查归档完整性，仍需在 Windows 真机验证安装、登录和下载。

页面结构或平台限制变化可能导致解析失败；失败会保留在任务中，不会默默遗漏并报告成功。
