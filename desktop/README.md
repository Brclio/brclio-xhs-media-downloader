## 安装与使用

从 [GitHub Releases](https://github.com/Brclio/brclio-xhs-media-downloader/releases) 下载对应系统安装包。Mac Apple 芯片选择 `mac-arm64.dmg`，Intel 芯片选择 `mac-x64.dmg`；Windows 选择 `windows-x64-setup.exe`（安装版）或 `windows-x64-portable.exe`（便携版）。

最终安装包自带运行环境，使用者不需要 Python、Node.js、Chrome 或 Vercel CLI。Mac 需要选择与芯片匹配的版本（Apple 芯片 arm64 / Intel x64），Windows 使用 x64 版本。

1. 安装并打开应用。原来的“单篇下载”保留网页版全部媒体功能和 Node.js / Python 引擎选择。
2. 切换“主页下载”，粘贴完整个人主页链接，例如 `https://www.xiaohongshu.com/user/profile/5e413a430000000001000f4c`。
3. 点击登录按钮，在应用的独立小红书窗口完成登录；成功后按钮显示“已登录 · 当前账号昵称”。如出现验证码，需要本人完成验证。
4. 选择保存文件夹，设置抓取间隔与额外随机等待，开始任务。Mac 首次访问“下载”或“文稿”文件夹时，请在系统提示中允许访问；从开发版切换为正式应用可能需要重新授权。
5. 等待列表收集和逐篇下载。可以暂停后继续；关闭应用后，下次打开需要手动继续任务。
6. 失败帖子旁可点击“重试”，也可一次重试全部失败项。任务正在运行时先暂停；重试不会重新请求成功的帖子，也不会改变序号。

主页列表通过小红书正常网页加载和滚动读取，详情通过同一登录会话打开。应用不使用猜测的 API 签名，不绕过验证码。只读取该作者发布的笔记，不收集点赞、收藏、关注者或相关推荐。

**Chrome、Codex 内置浏览器与下载器的登录状态互不共享。** 即使浏览器已经登录，下载器首次使用仍需在自己的窗口登录一次。之后账号会话仅保留在本机；退出登录、Cookie 过期或访问他人主页再次遇到登录检查时，任务会暂停，重新登录后可继续。

### Mac 钥匙串提示与重试

“小红书媒体下载器 Safe Storage”是应用沿用的系统安全存储名称，用于保护本机账号会话、设备密钥和浏览器登录信息。提示要求 Mac“登录”钥匙串密码，通常与 Mac 登录密码相同，不是邮箱密码或会员激活码。

从 v1.8.5 起，应用先显示窗口再异步读取安全存储；读取期间账号操作暂不可用，界面显示当前状态。拒绝授权或解锁失败时，原凭据和设备密钥仍保留。解锁系统钥匙串后可在软件账号页点击“重试安全存储”；若系统缓存了拒绝结果，需完全退出应用再打开。不要通过删除账号文件来处理钥匙串拒绝，否则可能失去原设备密钥。

当前 Mac 应用使用 ad hoc 签名，尚无 Apple Developer ID 签名及公证。更新或重装后的应用身份可能需要 macOS 再次确认，“始终允许”不能保证所有后续版本免提示。本版修复等待授权时的启动体验，不绕过系统安全存储或改用明文保存。

## “全部下载”的范围

“全部”指抓取期间该主页向当前登录账号公开展示、且可以打开详情的帖子。平台返回列表结束标记后才认定列表已完整；仅仅滚动没有新增内容不算结束。遇到登录、验证或列表停滞会保留进度并提示继续。

帖子可能在任务期间新增、删除或修改。已保存文件不会持续自动同步；要重新检查主页，请再次建立该主页任务。失败条目可重试。没有可下载媒体或不能确认完整详情的帖子会记为失败，不会只保存一张封面后当成成功。

默认请求间隔为 10 秒，加上最多 3 秒的随机等待。自定义间隔至少为 3 秒；每篇详情和每个媒体按队列顺序处理。正常网页本身仍会加载页面所需资源。间隔控制降低应用主动访问的频率，不能保证平台永不限流。

所选文件夹中，每篇帖子使用 `序号-帖子名称` 单独建目录，例如 `001-周末的海边散步`。序号按首次发现顺序分配，至少三位，继续和重试时不变；完整标题解析后更新目录名。标题中的跨平台非法字符会替换，过长标题会截短，无标题时使用兜底名称。旧版按笔记 ID 保存的目录及下载记录会兼容读取，处理对应帖子时迁移命名；不会覆盖不属于该帖的文件夹。

原图、实况 JPG + MP4、默认视频流、`笔记.txt` 和 `笔记.json` 一起保存。批量主页下载直接写入硬盘，不把整份主页媒体放进内存生成巨型 ZIP；单篇原有 ZIP 功能仍然可用。视频保存一个默认流，多清晰度可在单篇页选择下载。实况为配对素材，不会自动生成 Apple Photos 原生 Live Photo 元数据。

成功文件经过大小与 SHA-256 校验后才跳过；未完成媒体使用临时文件，完成后再改名。任务状态保存在应用用户数据目录，保留帖子链接、进度和目标路径；Cookie 由 Electron 的独立持久会话保存在本机，不写入任务清单。

## 检查和安装更新

从 v1.6.1 开始，应用启动后会检查 GitHub 上的最新正式版，也可点击“检查更新”。检查只提示版本，不会自动下载安装。点击下载后按当前系统和 CPU 架构获取安装包并显示进度。从 v1.8.2 开始支持暂停与断点续传：网络中断、超时或关闭软件后保留已下载部分，点击“继续下载”从保存的位置继续。缓存按版本、安装包和 SHA-256 区分，服务器不支持续传时会回退到完整下载；校验失败的文件会清除后重新下载。只有整个文件的大小和 SHA-256 校验通过才能启动安装。这些行为需要先安装 v1.8.2 后才能用于后续更新。

从 v1.8.4 起，当前应用进程已发现可信新版后，再次查询遇到限流或网络错误仍保留“下载更新／继续下载”。安装包和所需校验文件使用已知发布附件的直链，不要求重新查询最新版本。查询失败仅显示轻提示，文件下载失败才显示下载重试。已发现版本信息尚不跨进程保存；重启后仍需成功检查版本信息才能恢复进度。

从 v1.8.8 起，上次安装或临时旧版清理的结果显示在“关于软件”页，注明上次目标版本、当前运行版本和记录时间。历史提示不打开模态窗口，不暂停、覆盖或重置本次下载进度。关闭提示只持久保存该条记录的已读状态，不删除安装结果、恢复备份或当前安装指针；下次启动仍可按原安全条件重试清理。正在发生的下载错误和安装进度继续使用各自的提示。

发现新版本时显示更新弹窗，包含版本号、可滚动的更新说明，以及“稍后再说”和“立即更新”。同一版本在本次打开软件期间只自动弹出一次，手动检查更新可再次查看。弹窗中可以下载、暂停、继续和重试；“后台下载”只收起弹窗，仍会继续下载。下载完成后点击“安装并重启”，确认后进入覆盖安装流程。

下载完成后点击“安装更新”，应用内弹窗显示版本变化、任务保存与安装方式。点击“安装并重启”后应用会保存并暂停任务，打开安装包并退出当前版本；“稍后安装”、Esc、点击遮罩或退出应用都会取消尚未批准的安装。

- Windows：确认应用内更新后运行可见的安装程序，显示文件覆盖进度，安装成功后自动重新打开软件，无需点击“完成”才能启动。手动运行新版 setup 安装包覆盖安装时，安装完成后也会自动打开软件。便携版也下载 setup 安装包，因此会转为安装版；旧便携 EXE 不会被覆盖，请之后使用新版快捷方式。
- Mac：应用内更新有独立进度窗口，依次显示打开安装包、校验、复制、覆盖和启动等实际阶段；旧软件退出后窗口仍保持可见。验证对应芯片的 DMG 和新版应用后，等待旧进程退出，再在原位置覆盖安装并自动启动新版应用实例。v1.8.5 的安装助手等待新版窗口、页面和必要服务就绪的确认，随后才核对并清理临时旧版；系统接受“打开应用”请求不再被视为启动成功。替换、启动请求失败或启动确认超时时尝试恢复旧版；无法安全确认归属的恢复文件不删除。账号、任务和下载文件不属于清理范围。从 DMG 或只读位置运行时，请先将应用移到可写文件夹。手动从 Finder 拖放安装不属于应用内更新流程，仍需自行打开软件。用户自行保留的应用副本、早期改名前的另一份“小红书媒体下载器.app”不属于更新器备份，不会被搜索删除。

v1.8.7 继续使用原生文件系统清理经过归属校验的对应备份，避免 Electron ASAR 虚拟文件系统干扰删除。新应用启动时清除安装助手的 Node 运行环境，恢复旧版时也使用正常图形应用环境；界面初始化超过 10 秒或页面重载仍可确认真实就绪，退出或关闭窗口会取消等待。安装助手暂时持锁时，清理最多额外重试两次，每次重新核对身份、签名和目录；其他校验失败继续保留备份。

**v1.8.3–v1.8.6 自带的旧更新助手仍可能让新旧应用直接退出，不能依靠发布新版自动修好首次升级。** 请下载与芯片匹配的 v1.8.8 完整 DMG，等待现有安装结束，完全退出旧版后，将应用拖入原安装位置并选择替换，再从“应用程序”手动打开。此前版本也可使用这一路径；v1.8.7 可正常使用应用内更新。新版已完整安装并打开后，历史提示改进才会生效。不要删除账号文件、任务记录或下载目录来处理安装问题。

应用标识与用户数据目录保持一致，正常安装升级保留登录会话和任务记录。v1.6.3 改名后仍使用原名称的系统应用数据目录与账号会话，不复制或清空下载记录。升级后，原任务仍需手动点击继续。更新服务器暂不可达或网络中断时，可以重试，也可从 [Releases](https://github.com/Brclio/brclio-xhs-media-downloader/releases/latest) 手动下载。

**v1.5.0 及更早版本不具备更新入口，必须手动安装最新版一次。** 新功能无法远程写入已经安装的旧程序。应用内完整性校验不等同于 Apple / Windows 发布者代码签名，当前安装包仍未进行可信签名和 Apple 公证。

## 开发与发布

开发机才需要 Node.js（22 或更新版）和 Python（用于构建内置独立引擎）。普通使用者无需这些工具。

应用显示名称由 `build.productName` 和界面文案控制。顶层 `package.productName` 特意保留旧内部名：Electron 用它选择用户数据目录及 macOS Keychain 的 Cookie 加密密钥。请勿将顶层名称或 `app.name` 随显示名称一起修改，也不要更改 `build.appId`，否则可能无法读取原登录信息或识别旧安装。

```bash
npm ci
npm run desktop:dev
```

在 Mac 上构建当前芯片版本（采用固定版本、校验 SHA-256 的独立 Python，避免开发机的 Homebrew Python 抬高最低系统要求）：

```bash
npm run desktop:prepare:mac
npm run desktop:build:mac
```

在 Windows 上构建 x64 安装版与便携版：

```powershell
npm run desktop:prepare:windows
npm run desktop:build:win
```

输出在 `dist-desktop/`，文件名统一为 `Brclio-XHS-Downloader-版本号-系统-架构`：Mac 为 `.dmg` / `.zip`，Windows 为 `-setup.exe` / `-portable.exe`。例如 `Brclio-XHS-Downloader-1.8.0-mac-arm64.dmg`。Mac arm64 面向 Apple 芯片，最低 macOS 13；Intel Mac x64 由同一流程在 Intel 构建机或 CI 构建。Windows 包面向 Windows 10/11 x64。便携版同样包含完整运行环境，但任务与登录数据仍保存在当前系统用户的应用数据目录。

开发者可在 GitHub Actions 中手动运行 `Desktop installers`，或推送 `v*` 标签。矩阵分别构建 Mac arm64、Mac x64、Windows x64，先串行初始化 Electron 运行环境，再运行测试、真实 Electron 冒烟检查、归档源码比对和内置 Python 启动验证，避免并行测试竞争解压同一运行环境。推送与 package.json 一致的 `vX.Y.Z` 标签会在全部平台通过后自动发布。手动运行未填写 `release_tag` 时只上传 Actions 附件；填写已有 `vX.Y.Z` 标签时，明确检出 `refs/tags/vX.Y.Z` 并完成同一构建与发布流程。

发布前合并六个安装包并复核构建提交与 SHA-256；创建草稿前核对远端已有标签，确保其最终指向的提交与构建证据一致。上传全部附件并验证 GitHub 返回的文件摘要后，再次核对标签，确认未被移动才公开发布。不覆盖已经公开的版本，也不会因为版本标签缺失而隐式创建新标签。已有标签通过核验后，创建草稿只引用该标签，避免再次指定旧提交造成不必要的工作流写权限要求。

发布包必须包含对应操作系统、CPU 架构的 Python 引擎；缺少引擎时构建失败，本机原生构建还会实际启动引擎验证，不能产出要求用户自行安装 Python 的“完整安装包”。Release 附带 `SHA256SUMS.txt` 和 `build-evidence.json`，记录各平台源码提交、归档源码比对、运行时验证与安装包摘要。

发布脚本将 `docs/releases/vX.Y.Z.md` 第一行标题用于 GitHub Release 标题，正文自动去掉该行，并转换文档相对链接。发布说明顶部应提供六个品牌安装包的直接下载链接。为保持 v1.8.0 及更早客户端的更新兼容性，发布时额外保留两个 Mac DMG 和 Windows setup 的 `XHS-Downloader-...` 旧名副本，标为“旧版自动更新兼容包”；它们与对应品牌包逐字节相同，校验清单包含全部文件。新版更新器优先选择品牌包，也支持旧发布的文件名。历史 Intel 产物补发流程仍使用历史命名，不改变已经发布的版本标签或程序内容。

Mac 的 Apple 签名 / 公证和 Windows 的代码签名需要发布者配置自己的证书。未配置证书的构建是未签名测试包，分发时系统可能提示无法验证开发者。正式发布前应在目标系统上执行安装、启动、登录、下载和卸载验收。

## 验证与限制

```bash
npm test
```

另外可运行真实 Electron 验证（创建独立临时会话，不读取日常登录信息）：

```bash
node_modules/.bin/electron scripts/verify-desktop.mjs
node_modules/.bin/electron scripts/verify-profile.mjs
npm run desktop:verify:startup
```

测试覆盖原有 Node.js / Python 解析器、主页 URL 与列表完成判断、队列恢复、间隔等待、媒体下载边界、登录昵称和桌面协议。详情测试包含 Vue 循环引用、实况视频晚于图片加载、视频封面先于视频流加载的情况。桌面启动验证检查真实主进程、预加载桥接、两套引擎调用，并保存窗口截图。

v1.8.7 的流水线回归还检查安装助手启动新旧应用的环境隔离、真实 Electron 界面初始化超过 10 秒并重载后的就绪确认、取消等待及安装锁超时后的有限清理重试。安装包验证继续核对本版源码、内置运行环境和 SHA-256；实际结果以该版本工作流与构建证据为准，不能据此声明所有用户设备或 Windows 安装交互已验收。

2026-09-20 在 Mac 上使用实际登录会话验收：示例主页读到明确结束标记，共发现 240 篇；多图帖子、文案及 JSON 已实际落盘，实况 MP4 与普通视频样本也已下载并通过大小与 SHA-256 校验。登录按钮显示当前账号昵称，重启后恢复登录和任务。此验收不代表 240 篇均已下载完成。Windows 安装包已生成并检查归档完整性，仍需在 Windows 真机验证安装、登录和下载。

页面结构或平台限制变化可能导致解析失败；失败会保留在任务中，不会默默遗漏并报告成功。
