# v2.0.32：顺畅付款与会员结果同步

本版已发布（北京时间 2026-10-21），改进收银台打开、付款后返回客户端和会员结果显示。三平台原生门禁、11 个公开附件及网站与后端生产只读核验通过，见[操作审计](v2.0.32-operation-audit.json)。

## 本次更新

- **确认收银台是否交给系统浏览器**：Mac / Windows 通过受校验的主进程 IPC 打开支付宝或微信 HTTPS 收银台，等待系统接受打开请求。打开失败或超时时明确提示，可重试同一订单或复制原付款链接，不会因此再建一笔付款单。系统接受请求仍不代表浏览器页面已加载或付款完成。
- **付款后使用专用返回页**：新建的桌面订单返回 HTTPS 专用页面，无需在浏览器登录软件账号即可尝试打开客户端，也可点击「打开客户端」或手动切回软件。浏览器可能要求确认、拦截自动跳转或尚未登记客户端处理程序，本版不能保证所有浏览器自动唤回。
- **回到前台核实原订单**：客户端只把回跳中的订单编号作为查询提示，并核对原账号与已保存订单。冷启动、已打开窗口和切回前台都沿用订单恢复流程；未知订单、其他账号订单或重复提示不会直接开通权益，也不会替换正在处理的另一笔订单。
- **付款结果与会员结果清楚展示**：开通窗口显示套餐、金额、会员账号以及付款、核实订单、会员生效三个步骤。服务端确认付款后，继续刷新账号与两项功能权限，完成后显示会员结果和「完成，开始使用」。迟到的浏览器打开错误不会覆盖已经确认的结果；设备功能仍按授权限制执行。
- **下载进度保持可见**：开始视频下载时取消上次解析遗留的页面滚动，避免迟到的动画把进度移出视口；手动滚轮、触摸和键盘操作照常响应。
- **保留原有付款与会员记录**：在线支付宝、微信 Native、历史订单、已有会员时长、永久会员、激活码兑换及设备授权规则继续沿用。微信仍需另一台设备显示二维码后用手机扫码；本版不增加微信 H5、JSAPI 或原生 App 支付。

浏览器回跳、客户端被唤起、二维码展示或 SDK 成功都不是到账凭证。会员仍由服务端核实交易并持久保存后开通，重复查单与通知沿用同一幂等流程，不重复顺延会员。

## 安装与付款后返回

Mac / Windows 用户需安装或升级到 v2.0.32，并至少打开一次，才会向系统注册 `brclio-xhs` 回跳协议；仅更新网站或打开付款返回页不会更新旧客户端，也不会为旧程序补上该协议。系统默认程序及浏览器是否准许唤回取决于实际安装和本机设置；开发环境的模拟测试不代表用户当前安装已经完成注册或验收。

新建桌面订单使用专用 HTTPS 返回页，页面只传递业务订单编号，不携带登录令牌或「已支付」标记。浏览器如提示打开 Brclio，请按本人意愿确认；没有唤起时，可点击「打开客户端」，或手动打开下单时的软件账号，进入「开通会员」查询原订单。若选择「在网页登录查看」，仍需在网页中登录对应软件账号。

**旧订单保持原来的返回地址。** 已创建订单继续使用原收银台和返回 URL，不会为了增加唤回能力而重建订单。原网页返回入口可尝试打开客户端，也可手动切回软件查看「开通会员」或「我的全部订单」。请勿因为返回没有自动完成就重复付款。

正常覆盖升级沿用软件账号、主页任务与下载文件；请保留原数据目录。Mac v1.8.3–v1.8.6 首次升级仍需使用完整 DMG 覆盖并手动打开。Mac 当前使用 ad hoc 签名，尚无 Apple Developer ID 签名及公证；Windows 尚无发布者代码签名，系统安全提示和钥匙串授权限制继续保留。

Android 保持 1.0.15，本轮不发布新 APK。Android 现有账号及订单入口使用正式网站，浏览器页面随网站更新。
