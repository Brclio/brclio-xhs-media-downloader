官网的入口是 **Pages**：普通静态文件直接提供，`/api/*` 和 `/admin*` 经 `APP` 服务绑定进入主 Worker `brclio-xhs-downloader`。主 Worker 提供 Node 引擎、媒体下载、账号、后台和健康检查；Python 路径再经 `PYTHON_API` 私有服务绑定进入 `brclio-xhs-python`。两个 Worker 分别承担现有 Node 与 Python 功能。

控制台显示“无活动路由”不能据此判断 Worker 未被使用。本项目的 Worker 配置未声明 zone 路由，官网通过 Pages 和服务绑定调用；Python Worker 明确关闭公开 `workers.dev` 与预览地址。当前主 Worker、Pages 和两套生产引擎都已有实际响应证据，绑定另经只读元数据比对确认保留。

**Python 不应删除。** 前一轮网页发布时 Python 运行时源码未变，因此当时没有重新发布；这一说明仅属于历史状态。此后已发布原生诊断及私有渲染页面解析入口，当前 Python 版本为 `6d84f091-8d1c-426d-9eb6-5aa53cf06dd3`。当前网页和客户端的 `/api/python_parse`、`/api/python_image`、`/api/python_video` 仍依赖它，删除会破坏接口；主 Worker 和 Pages 同样有作用。

**最新 Cloudflare-only 补测仍未通过真实笔记验收。** 静态资源 180/180（首轮 3 项传输失败，各一次复核通过）、四入口关键资源 16/16、匿名边界 58/58 通过；这些不能代替真实解析成功。两次 Node 视频、一次 Python 视频及一次 Node 图文请求均为 422，没有验证入口。已捕获的浏览器诊断到达小红书错误页；图文请求不在 tail 窗口内，不推断其浏览器页面类型。浏览器自动重试因没有正向结果而停用，验证弹窗也未通过真实验收。普通请求先收到验证码页，浏览器实验又未取得正常笔记页；这是平台访问差异的直接证据，尚未精确隔离出口 IP、区域或实际线缆请求头等因素。最新状态见[浏览器尝试及停用报告](v2.0.15-cloudflare-browser-followup.json)与[部署说明](../cloudflare-deployment.md)。
