# v1.7.1 · Brclio 小红书下载器：Mac 应用包签名修复

本补丁修复 Mac 应用包的签名完整性问题。v1.7.0 的同配置构建在完整应用包检查中出现 `code has no resources but signature indicates they must be present`，这类签名与资源不一致的问题可能导致应用无法打开。

Mac 打包流程改为明确执行**完整应用包的 ad hoc 签名**。发布验证分别从最终 ZIP 解压应用、从最终 DMG 挂载取得应用，执行 `codesign --verify --deep --strict`；不能只检查打包前目录或其中一个可执行文件。

验证还会直接启动解压后的应用，在临时用户目录中检查真实界面与 Node / Python 两个解析入口，随后再次校验签名。此项使用测试钥匙串，不访问现有账号凭据；它证明安装包可以运行，不等于已通过另一台 Mac 的首次下载安全审批。

**ad hoc 签名不是 Apple Developer ID 签名，也不是 Apple 公证。** 本版仍可能出现 macOS 开发者或安全验证提示，不能承诺另一台 Mac 无提示打开。Windows 安装包也未配置发布者代码签名。

## 验证边界与 Mac 提示

**具体安装包是否通过验证，以本次发布工作流、`build-evidence.json` 与对应文件的 `SHA256SUMS.txt` 为准。** 发布门槛包含最终 ZIP 和 DMG 内应用的签名完整性校验；这项要求不能替代实际运行结果，也不能证明 Apple 已认可开发者身份或完成公证。

此前反馈无法打开的那台 Mac **仍待用户安装本补丁后人工确认**。操作系统重启、安装向导、覆盖升级，以及其他 Mac 上首次打开的完整验收，不因本次签名调整自动视为通过。

若提示无法验证开发者，且已确认下载来源和校验值可信，可按 [Apple 官方说明](https://support.apple.com/zh-cn/102445)，在“系统设置 → 隐私与安全性”中为这个应用单独选择“仍要打开”。这不会修复损坏的签名；若仍提示应用已损坏或签名检查失败，请保留错误信息并反馈，不要关闭系统范围的安全检查。

账号功能的已验证范围与限制见[验证记录](https://github.com/Brclio/brclio-xhs-media-downloader/blob/v1.7.1/docs/account-validation.md)。
