# v2.0.12

版本记录日期：2026 年 10 月 10 日（北京时间）。本版改进网页与 Mac / Windows「制作实况」的整包导出、iPhone 隔空投送、视频倍速及封面预览。Android 沿用 [v1.0.13](android-v1.0.13.md)。

## 本次改进

- 默认「下载实况包 ZIP」，在配对照片与 MOV 外增加完整 `.pvt` 包和 `metadata.plist`，导入说明位于包外。照片默认 HEIC，可选 JPEG；保留既有文件内配对标识和真实封面定时轨道。散件 ZIP、照片与 MOV 的分别下载收进备用入口。
- 在 Mac 解压 ZIP 后，通过 Finder 选中整个 `.pvt` →「共享 → 隔空投送」发送到 iPhone，在「照片」检查 LIVE / 实况标记并长按播放。保持包完整，不要打开包后分别发送照片与视频；直接发送 ZIP 也不能替代这一步。
- 成片支持 0.5–8 秒，提供 3 / 5 / 8 秒快捷选择。视频可选 1 / 1.5 / 2 / 3 倍速，取用的原视频长度为「成片时长 × 倍速」；不足的选项禁用。1 倍速可保留声音或静音，其他倍速成片统一静音，切回原速恢复声音选项。
- 片段播放、封面预览和编码使用一致的倍速与帧位置，包括不足一帧的片段末尾。修改素材、设置或导出格式会清除旧结果；可以取消并重新制作。

PVT 交接方式参考 [write-then-publish](https://github.com/fxyadela/write-then-publish#live-photo)，封装由本项目独立实现，保留既有 HEIC 编码与实况配对逻辑。素材继续在本机处理，无需会员。

## 时长与实机验证范围

0.5–8 秒是本工具支持的成片范围。Apple 的公开拍摄说明和资源接口不能据此归纳出适用于所有外部导入方式、设备与系统版本的统一最长时长；本轮保留 8 秒上限，优先发布已获手机确认的交接改进，不将 8 秒写作 Apple Live Photo 的标准上限。参考 [Apple 实况拍摄说明](https://support.apple.com/en-ie/104966)与 [PHLivePhoto 资源加载接口](https://developer.apple.com/documentation/photos/phlivephoto/request(withresourcefileurls:placeholderimage:targetsize:contentmode:resulthandler:))。

用户已在本次对话将两个完整测试包通过 Mac Finder 隔空投送到自己的 iPhone，并明确确认「两种格式都能作为实况接收并播放」：HEIC 样本为 2 秒，JPEG 样本为 3 秒。此次确认覆盖这两个包的接收和长按播放；未采集设备型号与 iOS 版本，其他时长和设备仍应检查实际接收结果。8 秒输出已获本机原生 Photos 框架识别，该结果不等同于 8 秒手机交接已实测。推荐先用 3 秒样本检查手机接收。详见[实况包与用户实机确认记录](../live-photo-pvt-verification.json)。

## 验证与发布流程

现有本机记录包含 1,128 项 Node 测试通过、12 项按条件跳过、27 项 Python 测试通过，网页与 Cloudflare Pages 构建通过；真实引擎、网页、桌面协议与桌面侧栏案例验证通过，未记录渲染错误。独立 FFmpeg 解码核对倍速画面映射与末帧封面，原生 Photos 框架核对实况资源识别，`unzip` / `plutil` 核对实际下载包。以上对应本机实现验证。发布流程另行检查最终提交的完整回归、三个原生安装包构建、升级门禁与线上网站，并按实际结果归档记录。

发布目标为 Mac Apple 芯片与 Mac Intel 的 DMG / ZIP、Windows x64 安装版与便携版，并沿用旧客户端自动更新兼容附件、SHA-256 清单和构建证据。发布流程核对公开附件、字节大小、GitHub Latest 与客户端更新入口，真实 CI、发布和官网核验结果以各自证据文件为准。

Mac 沿用完整应用临时签名，尚无 Apple Developer ID 签名及公证；Windows 尚无发布者代码签名。Android 本轮不发布新 APK。iCloud 同步全流程、壁纸使用及 Windows 相册识别不在本次手机交接验证范围内。
