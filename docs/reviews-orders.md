# 软件评价、个人订单与营业额

网页版首页的「用户评价」、Mac / Windows 客户端侧栏的「用户评价」展示相同公开评价。Android 的「软件评价与订单」入口在系统浏览器打开正式网站。任何软件账号均可评价，无需购买会员；每个账号只可发布一次，跨设备、网页和桌面共同限制。

评价为 1–5 星及 5–1000 字使用感受。发布前明确提示不可修改；公开只返回匿名昵称、评分、脱敏正文与时间，不返回账号邮箱或内部用户编号。评论按纯文本显示，不执行 HTML。并发发布与网络重试经过同一事务验证，成功响应丢失后重试原请求不会重复发表。

## 个人订单

在「账号与会员 → 我的全部订单」查看当前软件账号全部订单，采用服务端分页。付款后在「开通会员」选择实际购买套餐和支付渠道，点击「我已付款，提交核实」。提交生成待核实订单，不扣款、不自动开通会员。相同账号、套餐和渠道的已有待核实记录会复用，避免反复点击生成重复记录。

继续沿用日会员 ¥3、月会员 ¥19.9、年会员 ¥69.9，扫码付款、备注软件账号邮箱、人工核实并邮件发码的流程。订单、付款确认、发码和兑换为不同步骤；订单确认不会自行更改会员有效期。

## 后台收款与营业额

管理员登录 `/admin/`，在「订单与营业额」筛选邮箱、订单编号、收款流水号、状态及北京时间范围，分页可访问全部订单。待核实订单可直接选择确认，既有发码记录可选择核实，缺失订单也可选择软件账号补录。

确认收款须填写套餐、实际收到的人民币金额、渠道、收款时间、真实流水号和核实原因。激活码编号可选；若关联，必须与账号及套餐相符且未关联其他订单。相同渠道和流水号只可入账一次。记录与审计同一事务提交，网络结果不确定时复用原请求编号重试。若先确认收款再发码，可在已确认订单中关联对应激活码；关联只更新对应关系，不改变实收金额、流水或收款时间，也不会再次计入营业额。

营业额以已确认收款的实收金额为准，用整数分求和，以 `Asia/Shanghai` 收款日期筛选，支持按天、套餐和渠道汇总。待核实付款、发码数量、赠送会员和激活码兑换均不直接计入营业额。现有带套餐及价格的定向发码展示为「历史发码 · 收款待核实」，确认真实流水后才计入营业额；未保存的历史线下收款需要管理员核实补录，系统不会猜测实际收款。

## 存储与访问边界

沿用现有 GitHub 私有业务仓库和 SQLite 两种存储，在原版本状态上增量增加 `reviews`、`orders`，不修改 pepper、账号标识、激活码或旧审计。GitHub 乐观并发冲突会重新验证账号与业务条件；SQLite 使用原事务边界。

浏览器通过原 HttpOnly 同站 Cookie 登录，桌面通过原签名证明访问私有操作。个人接口只读当前账号，管理员接口要求管理员会话。前端在切换账号或退出时清除私有记录，丢弃迟到响应；评价与付款核实的不确定写入保留原请求编号。

本地验证：`npm test`、`npm run commerce:verify`、`npm run admin:verify:commerce`。正式发布沿用三平台打包、安装升级及 Android 签名/模拟器门禁。
