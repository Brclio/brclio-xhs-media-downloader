## 最终规则

| 时机 | 行为 |
| --- | --- |
| 开始、继续、重试主页任务；开始会员视频解析或保存 | 远程核验账号、会话、会员及设备，取得新签名凭证 |
| 逐篇、逐张、重定向、媒体重试 | 本地校验服务器签名及权限范围，不因媒体请求再次访问账号存储 |
| 下载进行中 | 主页任务每秒本地检查凭证，到期或本机退出后暂停；会员视频在请求和发布最终文件前检查，失效时拒绝发布。保留原文件和任务 |
| 后台同步 | 每 5 分钟刷新账号和已使用的会员权限；确认撤销或会员失效立即清除本地凭证 |
| 服务器暂时故障或断网 | 远程请求有限重试；仍失败时，仅在本机已有有效签名凭证的情况下继续 |
| 没有有效凭证 | 必须联网取得授权，不能用缓存中的会员文字、无签名 JSON 或管理员提示代替 |
| 旧服务器尚未配置签名 | 保持远程授权兼容和 30 秒长任务心跳；不再逐张校验，但不会假称具备离线权限 |
| 已使用签名的新客户端收到无签名响应 | 拒绝降级，要求修复签名配置或重新确认授权 |

每个凭证最长 24 小时，且 `expiresAt` 不能晚于会员到期时间。永久会员同样需要定期续签。联网正常时撤销在后台同步后生效；持续离线时，撤销最多延迟到已有凭证到期。这是短时离线续传与撤销及时性的明确取舍。

## 签名与本机存储

使用 Ed25519 非对称签名；私钥只配置在账号服务器，桌面包只固定可信公钥。签名覆盖密钥编号及完整载荷，校验固定算法、签发方、目标应用、账号、当前会话摘要、设备公钥摘要、功能和有效期。首次接收还校验此次请求的随机数，旧签名响应不能作为新凭证重放续期。复制凭证到其他设备、其他登录会话或其他功能不能获得权限。验证规则参考 [Node.js Crypto](https://nodejs.org/api/crypto.html) 和 [RFC 8725](https://www.rfc-editor.org/rfc/rfc8725.html) 对固定算法、签名与受众校验的要求；当前封装为固定格式的签名凭证，不接受客户端指定算法。

凭证随原设备凭据保存在 macOS Keychain / Windows DPAPI 保护的账号文件中。运行期间使用已验证的服务器签发时间及单调计时计算有效期，防止调回系统时间延长授权；重启时发现系统时间早于保存的时间锚则要求联网。离线使用的凭证不会被客户端自行续签。

普通单篇下载保持免费。网站继续使用服务器核验和原 Cookie 会话；本次本地验签用于受信任的桌面主进程，不将签名私钥或离线权限放进网页渲染器。

## 密钥准备与上线

```sh
node scripts/provision-entitlement-key.mjs
```

该命令创建 `data/entitlement-signing-key.pem`（权限 600，Git 忽略），仅把对应公钥写入 `desktop/account-config.json` 的 `entitlementPublicKeys.v1`。再次执行会复用原密钥，拒绝用同一编号覆盖不同公钥。不要重新生成后丢弃已准备的私钥，也不要将私钥复制进代码、桌面安装包、静态网页或日志。

密钥准备工具用于 Linux、macOS 或 WSL 的服务端发布环境，依赖 POSIX 私有文件权限；Windows 桌面用户无需运行它，客户端只使用已随安装包固定的公钥。

服务端配置：

- `AUTH_ENTITLEMENT_PRIVATE_KEY`：上述 Ed25519 私钥 PEM，使用平台 Secret。
- `AUTH_ENTITLEMENT_KEY_ID`：默认 `v1`，须与桌面固定公钥编号一致。

Cloudflare 可通过标准 Secret 输入配置，命令不会在终端打印私钥：

```sh
npx wrangler secret put AUTH_ENTITLEMENT_PRIVATE_KEY < data/entitlement-signing-key.pem
```

独立服务器及 Vercel 使用相同变量。可接受 PEM 中的真实换行或字面 `\n`。更新密钥时先发布同时信任新旧公钥的客户端，再切换服务器密钥编号；至少等待旧凭证的最长 24 小时有效期并确认客户端升级覆盖后，再考虑移除旧公钥。

必须分别完成服务端签名配置与部署、新桌面客户端打包发布，以及实际 Windows/macOS 安装后的长任务验收。旧的 2.0.7 客户端不会因为服务器多返回一个字段而自动获得本地验签能力。
